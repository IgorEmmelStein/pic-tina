# Blog Writing Workflow

Use this workflow for new posts and post improvements. The default deliverable is a schema-valid `.md` blog post file.

1. Confirm the task is blog-only.
2. Read `.agents/right-rudder-marketing/shared/outputs/brand-guide.md` and the aviation fact-check report or relevant aviation expert references.
3. Inspect the target repo's blog content schema and existing posts before writing.
4. Use the fact-check report `Topic Context` as the raw topic/title when the user did not repeat a topic in the blog-writing prompt.
5. Confirm search intent: informational, commercial investigation, comparison, cost guide, timeline guide, or explainer.
6. Convert the raw topic or title into an SEO-ready title, slug, meta description, post angle, human hook, reader stakes, byline mode, credited author, author evidence, permitted persona cues, personalization level, fallback voice, company POV, company-seat phrasing, sourced scene/example, qualifier strategy, client-confirmation handling, outline, CTA priority, section-by-section internal links, program page links, financing mention, `heroImage` candidate, and claims-to-check list.
7. Translate internal evidence into final-copy language before drafting. Do not publish repo labels, source notes, page-audit wording, transcript labels, or fact-check caveats as blog prose.
8. Write the post using approved claims only, with concrete aviation moments, student situations, and sourced company proof translated into lived context.
9. Use the company name for first-reference clarity, then use company-seat language for company-specific facts. Keep `you` and `your` more frequent than `we`, `our`, and `us`.
10. For team bylines, write as school staff. For named authors, keep persona cues light and source-backed; if no usable author background exists, keep the byline and use team voice.
11. Add FAQ and CTA near the end. FAQ should answer real buying friction, and the CTA should point to one primary next step.
12. Run `blog-quality-gate.md` before writing the final file, including table program links, per-section internal backlinks, financing mention, bold emphasis where useful, `heroImage` uniqueness, editorial headings, human opening, company-seat language, byline honesty, source-audit phrase removal, and qualifier placement.
13. Create one `.md` file in the resolved blog content folder, unless the user explicitly asks for draft-only output.
14. Run the image/link validator and the human voice linter before delivery. Revise until both pass.

If the brand guide lacks proof, examples, or verified claims for the topic, ask for the missing artifact instead of padding the article.
