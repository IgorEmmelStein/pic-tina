# Fact-Check Output Contract

Use this structure for aviation fact-check reports.

```markdown
# Aviation Fact-Check Report: [Raw Blog Topic Or Draft Name]

## Topic Context
- Raw blog topic/title:
- Intended content type: blog post
- Brand guide used:
- Repo/source context used:
- Topic notes for writer:

## Sources Consulted
- [reference file or source path]: [topic]
- User-provided information dump: [topic, if supplied]

## Claims Reviewed
| Claim | Classification | Source | Notes | Safer Rewrite |
| --- | --- | --- | --- | --- |
| [claim] | verified | [source] | [short note] | [optional] |

## Writer Use Guidance
- Use confidently:
- Safe vivid framing:
- Required qualifier, if any:
- Where to place the qualifier:
- Do not over-qualify:
- Internal source language not for final copy:
- Client-confirmation handling:

## Needs Client Confirmation
- Claim:
- Question:
- Why it matters:

## Do Not Use
- Claim:
- Reason:
- Safer direction:

## Writer Instructions
- Approved language:
- Use confidently:
- Safe vivid framing:
- Avoid:
- Required qualifiers:
- Where to place qualifiers:
- Do not over-qualify:
- Internal source language not for final copy:
- Final-copy perspective:
- Author/persona constraints:
- Client-confirmation handling:
- Topic to use for blog planning:
```

Keep the report concise enough for the blog writer to act on quickly. Do not turn every caution into a blanket disclaimer. Give precise limits so the writer can be accurate and still write with energy. Mark source-audit language, including `our [topic] page lists` and `our website says`, as internal only, and give the writer company-voice alternatives when a verified fact can be used confidently.
